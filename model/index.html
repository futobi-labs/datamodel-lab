The JSON shape

Six top-level keys. Only layers, tables and columnLineage are required; the rest switch on extra views.

KeyWhat it holdsUsed by

Swapping in your own model

Each piece of the JSON has a natural source in a real platform. None of these exports needs anything exotic:

  • Tables and columns: INFORMATION_SCHEMA.COLUMNS from the Warehouse and the lakehouse SQL analytics endpoint, one query per layer.
  • Bronze and silver lineage: the pipeline config table already says which source object lands in which target; column edges are pass-through by default, then hand-annotate the renames and derivations.
  • Gold lineage: parse the load stored procedures, or keep a small mapping table next to them. A mapping table you maintain beats a parser you don't.
  • Semantic layer and measures: the TMDL or model.bim export of the semantic model, or INFO.TABLES(), INFO.COLUMNS(), INFO.RELATIONSHIPS() and INFO.MEASURES() DAX functions run from a notebook with semantic link.
  • Report visuals: the report definition (PBIR) lists each visual's fields and measures.
In Microsoft Fabric

A single notebook can do all of it: query the SQL endpoints for columns, read the control table for bronze, call semantic link for the model, and write one JSON file to a lakehouse Files folder. Commit that file here and every exploration redraws with your model.
