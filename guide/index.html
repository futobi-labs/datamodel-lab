Field Guide

What is commonplace in data modeling today, written down plainly: opinions where practice has settled, and open questions where it has not.

These pages are for practitioners who build lakehouses, warehouses and semantic models for a living: data engineers, analytics engineers and BI architects who already know what a star schema is and want a compact, opinionated reference for the decisions that come up every week. Where common practice is clear, the guide says so and gives a rule. Where it is not, it names the deciding factor instead of hiding behind "it depends."

Every example uses the same small, generic order-to-cash and inventory model: ERP, CRM and file sources landing in bronze, cleaned into silver, shaped into a gold star (fact_sales, fact_inventory_daily, fact_budget), and served by the "Sales & Inventory" semantic model behind two reports. The explorations visualize that same model, so any page here can be seen there. Platform specifics are written for Microsoft Fabric, though most of the guidance carries to Databricks, Snowflake or any other lakehouse.

How to read these pages

Watch out

A common failure mode, usually one that produces numbers that look right until someone checks.

Open question
